# Project Context: SecOps Recon

## Overview
SecOps Recon is an Electron-based Application Security platform orchestrating multiple DAST and Reconnaissance tools. It acts as a wrapper around Open Source CLI tools (Nuclei, Wapiti, WPScan, ProjectDiscovery suite, Nmap, FFUF, ZAP) and Commercial Desktop/API tools (Acunetix, HCL AppScan, Invicti Netsparker) to provide a unified Graphical User Interface (GUI) for executing security assessments, reading logs in real-time, and managing reports.

## Technology Stack
- **Framework**: Electron (via `vite-plugin-electron`)
- **Frontend Engine**: React 19, TypeScript, Vite
- **Styling**: TailwindCSS v4
- **Terminal Emulator**: xterm.js (`xterm`, `@xterm/addon-fit`, `@xterm/addon-search`)
- **Icons**: lucide-react
- **Routing**: react-router-dom (HashRouter used for Electron compatibility)

## Directory Structure
- `electron/main.ts`: The main process entry point. Manages window creation.
- `electron/preload.ts`: The preload script establishing the `contextBridge` for secure IPC.
- `electron/ipc.ts`: Defines the main process IPC handlers (`scan:start`, `scan:stop`, etc.).
- `electron/services/scanner.ts`: Manages the lifecycle of `child_process.spawn` for CLI tools and Docker containers.
- `electron/services/storage.ts`: Handles file system writes, creating directories under `Documents/SecOpsScans`.
- `electron/services/logger.ts`: Writes application logs to `Documents/SecOpsScans/logs/application.log`.
- `electron/services/aiService.ts`: Manages AI integrations and automatic Ollama local daemon orchestration.
- `electron/scripts/acunetix_runner.js`: Node.js script for polling the Acunetix REST API, managing Docker states, and downloading XML/PDF reports.
- `src/App.tsx`: Main React application and layout with sidebar navigation.
- `src/components/TerminalPane.tsx`: Reusable xterm.js wrapper component for live console outputs using `requestAnimationFrame` for stability.
- `src/pages/`: Contains the Dashboard, History, and Settings views.

## Architectural & Security Decisions
1. **No Node Integration in Renderer**: `nodeIntegration` is strictly `false`. `fs` and `child_process` modules are exclusively used in the `electron/` backend.
2. **Safe Command Execution**: Commands are never executed via `exec` with concatenated strings (except for explicit daemon launches). `spawn` is used with string arrays to prevent shell injection.
3. **Containerized Execution**: WPScan and Acunetix rely on local Docker daemons (`docker run`) mapped to local volumes, isolating their dependencies from the host OS.
4. **Data Persistence**: Scan history is inferred dynamically by reading the metadata files stored in the generated report folders, rather than relying on a separate database.
5. **AI Integration**: Features AI Log Analysis via local `ollama` (with auto-pull capabilities) and cloud APIs (OpenAI, Gemini, Anthropic) to generate executive summaries.
6. **Robust Parsing**: Integrates `fast-xml-parser` for proprietary XML reports (AppScan, Netsparker, Acunetix) and parses line-delimited JSON for OSS tools to populate unified findings.
